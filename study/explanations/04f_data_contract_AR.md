# الفصل 04-و: عقد البيانات والمصدر الموحد للحقيقة (Data Contract)
## Chapter 04f: The Single Source of Truth & Runtime Zod Contracts

في المشاريع الكبيرة التي تحتوي على عدة لغات برمجية (TypeScript في الواجهة والـ Gateway، و Python في الذكاء الاصطناعي، و C/C++ في شريحة ESP32)، أكثر مشكلة تسبب كوارث برمجية هي **تشتت هياكل البيانات (Schema Drift)**؛ كأن يُسمى حقل في بايثون باسم مختلف أو يتم إرسال رقم كـ String بالخطأ.

لحل هذه المعضلة بالكامل، بنينا حزمة مستقلة اسمها **`@thenar/contracts`** داخل المجلد `packages/contracts`.

---

### 1. مبدأ المصدر الموحد للحقيقة (Single Source of Truth)
كل كائن، وكل رسالة WebSocket، وكل جدول بيانات تم تعريفه **مرة واحدة فقط** في ملف `packages/contracts/src/index.ts` باستخدام مكتبة **Zod**:
- يتم توليد أنواع لغة TypeScript تلقائياً من الـ Zod Schemas (`z.infer<typeof ...>`).
- يتم استيراد نفس هذا العقد في الـ Gateway، والواجهة الأمامية، ومحاكي الأجهزة.
- تم اشتقاق ملف مواصفات الـ REST العالمي (`openapi.yaml`) من نفس هذه القواعد.

---

### 2. تفصيل الكائنات الأساسية في العقد

#### 1. كائن المحاولة البيومترية (`Attempt`)
يمثل التوثيق الرسمي لكل حركة فتح للخزنة:
```typescript
{
  id: "att_1730840000_123",       // معرف فريد للمحاولة
  sessionId: "sess_S4_01",         // رقم الجلسة
  ts: 1730840000000,               // الوقت بالمللي ثانية
  fingerprint: {
    result: "accept",              // نتيجة الحارس الأول
    templateId: 1
  },
  score: -2.35,                    // سكور الحارس الثاني s(x)
  tau: -3.85,                      // عتبة القرار المطبقة
  decision: "accept",              // القرار النهائي
  failureCounterAfter: 0,          // عداد الفشل بعد المحاولة
  durations: {
    touchMs: 380,                  // زمن وضع الصباع
    timeToPeakForceMs: 840,        // زمن الوصول لأقصى ضغط
    rotationMs: 620,               // زمن لف المقبض
    totalMs: 2150                  // إجمالي زمن الحركة
  },
  featureDeviations: [],           // الخصائص الشاذة (لو مرفوضة)
  flags: ["normal_unlock"],        // رايات أمنية
  role: "genuine"                  // هوية المنفذ
}
```

#### 2. كائن حالة القفل الميكانيكي (`LockStatus`)
يعكس الحالة الكهربية والميكانيكية لحظة بلحظة:
```typescript
{
  door: "closed",                  // حالة مفتاح الـ Reed (الباب مقفول/مفتوح)
  bolt: "extended",                // وضع اللسان الفولاذي (ممتد/مسحوب)
  solenoid: "off",                 // تفعيل ملف السولينويد الكهربي
  state: "idle",                   // حالة آلة الحالة المنتهية
  failureCount: 0,                 // عدد المحاولات الفاشلة
  lockoutUntil: null               // توقيت انتهاء الإغلاق الأمني
}
```

#### 3. كائن تصدير النموذج الرياضي (`ModelExport`)
يخرج من خدمة بايثون ليوجه معالج المقبض:
- `featureNames`: مصفوفة بأسماء الـ 16 خاصية بترتيبها المعياري الصارم.
- `mean`: المتوسطات الحسابية لخصائص المالك الحقيقي.
- `scalingMean` و `scalingStd`: معاملات التطبيع الإحصائي.
- `covInv`: مقلوب مصفوفة التباين المشترك المنكمشة ($16 \times 16$).
- `tau`: عتبة القرار المحسوبة.

---

### 3. التحقق الصارم في زمن التشغيل (Runtime Zod Validation)
في لغة TypeScript، الأنواع (Types) تختفي تماماً بعد ترجمة الكود (Compile Time) ولا تحمي السيرفر أثناء التشغيل الحقيقي.
لكن مع **Zod**:
عندما يصل أي طلب للـ Gateway، تقوم الدالة `AttemptSchema.safeParse(req.body)` بفحص كل حقل وقيمته في زمن التشغيل (Runtime). لو أرسل المهاجم حقلاً ناقصاً أو نصاً في مكان الرقم، يرفض السيرفر الطلب فوراً بخطأ 400 ويوضح الحقل الخاطئ بالتفصيل، مما يجعل السيستم محصناً تماماً ضد البيانات التالفة.
