# الفصل 04-د: خدمة المعايرة والتعلم الآلي (Python FastAPI Service)
## Chapter 04d: The Python Offline Enrollment Toolchain & Ledoit-Wolf Shrinkage

في مقترح مشروع Thenar، تم تحديد أن عملية تدريب ومعايرة نموذج الذكاء الاصطناعي للبصمة الحركية للمالك (Owner Biometric Profile) تتم عبر **سلسلة أدوات غير متصلة (Offline Toolchain)**. في هذا الإصدار، قمنا ببناء هذه السلسلة كخدمة برمجية مستقلة مبنية بـ **Python 3 + FastAPI + scikit-learn** داخل المجلد `apps/enrollment`.

### 1. لماذا نحتاج خدمة Python منفصلة؟
مكتبات بايثون العلمية (`scipy`, `numpy`, `scikit-learn`) هي المعيار الأكاديمي والصناعي العالمي لحسابات الجبر الخطي المتقدم ومصفوفات التباين المشترك المنكمشة (Covariance Shrinkage).
عبر فصل هذه الحسابات في خدمة بايثون خفيفة تعمل على المنفذ `8000`:
- يظل كود الـ Gateway في Node.js بسيطاً وسريعاً في معالجة طلبات الـ WebSockets والـ REST.
- يتم تنفيذ العمليات الرياضية المعقدة في بايثون بكفاءة عالية، ثم تصدير مصفوفة النتائج الجاهزة كملف C Header (`thenar_model.h`) ليتم رفعها على ذاكرة شريحة ESP32 مباشرة!

### 3. ما هو انكماش ليدوا-وولف (Ledoit-Wolf Shrinkage) ولماذا نستخدمه؟
في الإحصاء، إذا كان لديك 16 خاصية ($D = 16$) وأردت حساب مصفوفة التباين المشترك ($\Sigma$) بحجم $16 \times 16$، فإنك رياضياً تحتاج إلى مئات أو آلاف العينات حتى لا تكون المصفوفة شاذة (Singular Matrix / Determinant = 0).
لكن المالك لن يقوم بلف المقبض 500 مرة ليعاير خزنته! المالك سيلف المقبض **5 مرات فقط** ($N = 5$).
هنا تحدث مشكلة علمية كبرى: **$N < D$ (عدد العينات أصغر بكثير من عدد الخصائص)**!

> **حل عبقرية ليدوا-وولف (The Ledoit-Wolf Solution):**
> خوارزمية Ledoit-Wolf تقوم بدمج مصفوفة العينات الفعلية الصغيرة مع مصفوفة تطابق قطرية (Identity Target Matrix) باستخدام معامل انكماش محسوب رياضياً بدقة ($\alpha$):
> $$\Sigma_{\text{shrunk}} = (1 - \alpha) \Sigma_{\text{sample}} + \alpha \frac{\text{Tr}(\Sigma)}{p} I$$
> **النتيجة:** مصفوفة تباين مشترك مقلوبة ($\Sigma^{-1}$) ومستقرة رياضياً بنسبة 100% ومستحيل أن تكون شاذة أو تعطي قيماً لانهاية!

### 4. معايرة العتبة بقاعدة المالك فقط (Leave-One-Out Calibration)
> **قاعدة الأمان الأكاديمية (Strict Owner-Only Rule):**
> لا يجوز مطلقاً استخدام أي بيانات لمهاجمين أو غرباء لحساب عتبة القرار $\tau$! النظام يجب أن يحدد عتبة أمانه بالاعتماد الحصري على بيانات المالك الحقيقي.

نحقق ذلك عبر تقنية **التحقق التقاطعي باستبعاد عينة واحدة (Leave-One-Out Cross-Validation)**:
1. لو كان لدى المالك 5 محاولات ($T_1, T_2, T_3, T_4, T_5$).
2. ندرب النموذج على ($T_2, T_3, T_4, T_5$) ونحسب سكور المحاولة المستبعدة $T_1$.
3. نكرر نفس الشيء مع كل محاولة، فنحصل على 5 سكورات حقيقية للمالك الحقيقي في أضعف حالاته.
4. نأخذ المئين الخامس (5th Percentile) لهذه السكورات كقيمة للعتبة $\tau$.
5. هذا يضمن أن 95% من حركات المالك الطبيعية سيتم قبولها بنجاح حتى لو كان متعباً أو على عجلة من أمره، بينما أي حركة غريبة ستسقط حتماً تحت هذه العتبة!

### 5. تصدير كود لغة السي للمايكروكنترولر (`thenar_model.h`)
تقوم الدالة `export_c_header` بتحويل المصفوفات الحسابية إلى كود C مباشر خفيف جداً يمكن نسخه وضمه فوراً في كود الأردوينو أو ESP-IDF لشريحة ESP32:

```c
/* Auto-generated by Thenar Enrollment Toolchain */
#ifndef THENAR_MODEL_H
#define THENAR_MODEL_H

#define THENAR_NUM_FEATURES 16
#define THENAR_DECISION_TAU -3.850000f

static const float THENAR_FEATURE_MEANS[THENAR_NUM_FEATURES] = {
    2.150000f, 0.380000f, 0.900000f, 0.880000f, /* ... */
};

static const float THENAR_COV_INV[THENAR_NUM_FEATURES][THENAR_NUM_FEATURES] = {
    { 0.124500f, -0.015000f, ... },
    /* ... 16x16 Inverted Matrix ... */
};

#endif
```
المعالج المدمج (ESP32) يأخذ هذا الملف ويحسب مسافة ماهالانوبيس في 2 مللي ثانية فقط على الشريحة بدون الحاجة لأي اتصال بالإنترنت!
