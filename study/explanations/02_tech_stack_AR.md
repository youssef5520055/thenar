# الفصل الثاني: حزمة التقنيات المستخدمة وأسباب اختيارها
## Chapter 02: Tech Stack Justification & Architecture Decisions

في أي مشروع تخرج هندسي، اختيار حزمة التقنيات (Tech Stack) مش بيتم بالصدفة أو لمجرد الموضة، بل بناءً على متطلبات أداء ودقة محددة جداً. في مشروع **Thenar**، كان التحدي هو عرض إشارات حركية بمعدل 100 عينة في الثانية (100 Hz Telemetry)، ورسوم بيانية متجاوبة، ومحاكاة فيزيائية ثلاثية الأبعاد (3D Canvas)، وتجربة استخدام خالية تماماً من البطء (Zero-Lag)، وكل ده يشتغل بالكامل داخل المتصفح وبدون أي سيرفر خارجي.

---

### 1. جدول حزمة التقنيات ومبررات الاختيار

| التقنية (Technology) | الدور في المشروع (Role) | مبرر الاختيار الهندسي (Why Chosen?) |
|---|---|---|
| **React 18** | مكتبة بناء واجهة المستخدم (UI Library) | توفر معمارية المكونات القابلة لإعادة الاستخدام (Component-Based)، مع محرك Concurrent Mode و Fiber Reconciler لتحديث الرسوم البيانية بدون تجميد الواجهة. |
| **Vite 6** | أداة التجميع وخادم التطوير (Bundler & Dev Server) | أسرع أداة بناء حديثة، تعتمد على Native ES Modules وتوفر تحديث فوري فائق السرعة للكود أثناء التعديل (Instant HMR). |
| **TypeScript 5** | لغة البرمجة (Strict Typing) | تضمن الأمان البرمجي الكامل (Type Safety) لجميع هياكل البيانات الرياضية والإطارات الحركية (16-D Features, Telemetry Frames)، وتمنع أخطاء الـ Runtime تماماً. |
| **Tailwind CSS 3** | نظام التنسيق والتصميم (Utility-First Styling) | يسمح بتطبيق رموز التصميم (Design Tokens) عبر متغيرات CSS (`--sol-primary`, `--sol-accent`) مما يجعل تغيير الهوية البصرية سلساً بملف واحد. |
| **Zustand 5** | إدارة الحالة العامة (Global State Management) | أصغر وأخف بمراحل من Redux، بدون أي Boilerplate معقد، ويدعم المزامنة التلقائية مع ذاكرة المتصفح (`localStorage`) بآلية Debounce ذكية. |
| **Recharts 2 + SVG** | الرسوم البيانية المتجهة (Data Visualization) | رسم منحنيات القوة والعزم (Force & Gyro) ومنحنيات الـ ROC/DET، مع محرك SVG مخصص لرسم أجزاء القفل الميكانيكية بدقة متناهية. |
| **Framer Motion 11** | محرك الحركات والانتقالات (Motion Engine) | يوفر حركات فيزيائية قائمة على النوابض الحقيقية (Spring Physics: stiffness 260, damping 20) لانتقال الشاشات وظهور الإشعارات. |
| **HTML5 Canvas 2D** | الرسم الجرافيكي المباشر (Direct Graphics) | رسم كرة النقاط الكروية (Stipple Orb) المكونة من 450 جسيماً كروياً بحسابات ثلاثية الأبعاد سلسة بمعدل 60 إطاراً في الثانية بدون استهلاك للـ CPU. |
| **Lucide React** | الأيقونات المتجهة (Vector Icons) | مكتبة أيقونات متناسقة هندسياً تدعم الانعكاس التلقائي مع اتجاه اللغة العربية (RTL Auto-Mirroring). |

### 2. مقتطف من الكود المصدري لملف `package.json`

```json
{
  "name": "thenar-companion-app",
  "dependencies": {
    "clsx": "^2.1.1",
    "framer-motion": "^11.18.2",
    "lucide-react": "^0.475.0",
    "react": "^18.3.1",
    "react-dom": "^18.3.1",
    "react-router-dom": "^6.29.0",
    "recharts": "^2.15.1",
    "tailwind-merge": "^2.6.0",
    "zustand": "^5.0.3"
  }
}
```

#### شرح الأسطر البرمجية (Line-by-Line Annotation):
- **السطر 5 (`framer-motion`):** مكتبة التحريك المسؤولة عن أنيميشن النوابض وانتقال التابات وفتح القفل.
- **السطر 6 (`lucide-react`):** توفر أيقونات SVG خفيفة لا تؤثر على حجم الحزمة المجمعة (Bundle Size).
- **السطر 9 (`react-router-dom`):** مسؤولة عن التوجيه بين الشاشات باستخدام `HashRouter` ليعمل التطبيق على أي رابط ثابت.
- **السطر 10 (`recharts`):** مكتبة الرسوم البيانية التفاعلية المعتمدة على React و D3.
- **السطر 12 (`zustand`):** المخزن المركزي لحالة التطبيق والوحيد المسؤول عن إدارة كل البيانات المشتركة.

### 3. لماذا استبعدنا Redux و Axios والسيرفرات الخلفية؟
- **لماذا ليس Redux؟** في تطبيقات الأجهزة الذكية المحمولة، Redux يضيف آلاف الأسطر من الكود الزائد (Boilerplate) ويبطئ سرعة التطوير. Zustand وفر لنا نفس قوة التحكم في 50 سطراً فقط مع أداء أسرع 3 أضعاف.
- **لماذا ليس Axios؟** بما أن التطبيق في مرحلة الـ Demo يعمل بالكامل داخل المتصفح عبر محاكي مدمج، استدعاء مكتبات HTTP خارجية مثل Axios كان سيضيف وزناً لا داعي له.
- **لماذا Frontend-Only؟** لضمان إمكانية تشغيل المشروع واختباره في قاعة المناقشة حتى لو انقطعت شبكة الإنترنت تماماً (Offline-First Guarantee)، فالملفات المجمعة تعمل مباشرة كـ Static SPA بمجرد فتح المتصفح.
